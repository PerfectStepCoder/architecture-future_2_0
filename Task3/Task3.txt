
1) Сформируйте технический радар
    
    Легенда:

    - Adopt (Внедряем) — проверенные технологии, которые стоит использовать сейчас
    - Trial (Пилотируем) — перспективные, но требующие тестирования
    - Hold (Замораживаем) — устаревшие или неэффективные решения
    - Assess (Оцениваем) — технологии для изучения в будущем

    | Категория	     |    Adopt                     |	Trial                   |	Hold                      |	Assess                                |
    | -------------- | ---------------------------- | ------------------------- | ----------------------------| ------------------------------------- |
    | Хранилища	     | Snowflake, PostgreSQL        | MongoDB (для JSON-данных)	| SQL Server 2008	          | ClickHouse (для аналитики)            |
    | Интеграция	 | Apache Kafka, REST API       | Apache Airflow	        | Apache Camel	              | GraphQL                               |
    | BI & Аналитика |	Power BI, dbt               | Metabase	                | Устаревшие кастомные отчёты |	Looker                                |
    | Безопасность	 | Azure AD, RBAC               | HashiCorp Vault	        | Локальные права в DWH	      | Zero Trust Architecture               |
    | Разработка	 | Python (ИИ), Golang (Финтех) | React (новый BI-интерфейс)| Power Builder	              | Rust (для высоконагруженных сервисов) |
    | ----------------------------------------------------------------------------------------------------------------------------------------------- |

    Обоснование решений:

    - Adopt
    Snowflake: Замена DWH — облачное масштабирование, поддержка мультидоменной архитектуры.
    Kafka: Потоковая интеграция доменов вместо устаревшей шины (Camel).
    Power BI + dbt: Стандартизация BI с декларативными трансформациями.
    
    - Trial
    MongoDB: Для неструктурированных медицинских данных (например, геномные исследования).
    Metabase: Пилот для Data Marketplace (альтернатива дорогим BI-инструментам).
    React: Постепенный отказ от Power Builder в пользу веб-интерфейсов.
    
    - Hold
    SQL Server 2008: Не поддерживается Microsoft, риски безопасности.
    Apache Camel: Медленная и сложная в поддержке шина.
    Power Builder: Устаревший UI-фреймворк, несовместимый с современными стандартами.
    
    - Assess
    ClickHouse: Для высокоскоростной аналитики (если Snowflake окажется дорогим).
    Zero Trust: Повышение безопасности в распределённой системе.
    Rust: Для критичных финтех-сервисов (например, процессинг платежей).

2) Составьте роадмап
   
   Горизонт: 12 месяцев. Цель: Переход от монолитного DWH к доменно-ориентированной архитектуре с Data Marketplace

   Сыллка на диаграмму: https://drive.google.com/file/d/1eSZfV-YuIZnRH_ChBrnceB52sI0QcnIp/view?usp=sharing
   (вкладка: "Stages")

3) Обоснуйте изменения

    1) Анализ и планирование (Месяц 1)       
        Проблема: Сейчас нет чёткой архитектурной стратегии, что ведёт к хаотичным изменениям в DWH
        Решение:
        - Аудит текущих систем и данных
        - Выбор облачного провайдера (AWS/GCP/Azure) на основе TCO-расчётов
        - Определение границ доменов (медицина, финтех, ИИ)
        Результат: Чёткий план миграции, исключающий дорогостоящие ошибки

    2) Миграция DWH → Snowflake (Месяцы 2–3)
        Проблема: SQL Server 2008 не поддерживает масштабирование, тормозит аналитику
        Решение:
        - Перенос данных в облачное хранилище (Snowflake/BigQuery) с сохранением исторических отчётов
        - Настройка Change Data Capture (CDC) через Kafka для реального обновления данных
        Результат: Данные доступны для аналитики в 5 раз быстрее, снижение нагрузки на легаси-системы

    3) Запуск Data Pipeline (Kafka + Airflow) (Месяцы 3–4)
        Проблема: Текущая шина (Apache Camel) не справляется с потоковой обработкой
        Решение:
        - Kafka для событийной интеграции доменов (например, платежи → аналитика)
        - Airflow для оркестрации ETL-процессов
        Результат: Данные между доменами синхронизируются в реальном времени без ручных выгрузок

    4) BI-портал самообслуживания (MVP на Metabase) (Месяцы 4–6)
        Проблема: Сотрудники ждут отчёты часами, нет возможности строить кастомные дашборды.
        Решение:
        - Развёртывание Metabase (open-source) с доступом к витринам в Snowflake
        - Подключение ключевых дашбордов для финтеха и клиник
        Результат: Пользователи получают данные за минуты, а не часы

    5) Разделение доменов (Месяцы 6–8)
        Проблема: Все бизнесы зависят от DWH, изменения в одном ломают другие
        Решение:
        - Клинический домен: PostgreSQL с FHIR-стандартом для медицинских данных
        - Финтех-домен: Транзакции в Kafka + PostgreSQL для ACID-требований
        - ИИ-домен: Feature Store (Hopsworks) для ML-моделей
        Результат: Независимое развитие направлений, отсутствие каскадных сбоев

    6) Безопасность и IAM (Месяцы 9–10)
        Проблема: Данные пациентов и платежей смешаны, нет единого контроля доступа
        Решение:
        - RBAC (ролевая модель) через Azure AD
        - Шифрование данных в движении и покое (HashiCorp Vault)
        Результат: Соответствие 152-ФЗ, GDPR, PCI DSS

    7) Оптимизация BI (Looker/Redis) (Месяцы 11–12)
        Проблема: Metabase может не справиться с нагрузкой при масштабировании
        Решение:
        Внедрение Looker (Google Cloud) для сложной аналитики
        Кэширование запросов через Redis
        Результат: Поддержка 1000+ пользователей без падения производительности

    8) Документация и обучение (Месяц 12)
        Проблема: Сотрудники не умеют работать с новыми инструментами
        Решение:
        - Гайды по Data Marketplace, API-документация для разработчиков
        - Воркшопы по Snowflake, Kafka, Metabase
        Результат: Снижение сопротивления изменениям, ускорение адаптации

    Влияние на бизнес-целями

    | Этап	               | Как влияет на бизнес?                                                 |
    | -------------------- | --------------------------------------------------------------------- |
    | Миграция в Snowflake | Ускоряет отчётность → быстрее принятие решений                        |
    | Разделение доменов   | Позволяет добавлять новые бизнесы (фармацевтику) без переделки DWH    |
    | BI-портал	           | Снижает нагрузку на IT (сотрудники сами строят отчёты)                |
    | Безопасность	       | Уменьшает риски штрафов за утечки данных                              |
