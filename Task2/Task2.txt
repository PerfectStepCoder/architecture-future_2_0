
1) Разделите систему на домены

    Выделенные домены

        Каждый домен:
        - Имеет свою базу данных (независимую от DWH).
        - Общается через API или события (Kafka).
        - Управляет своими данными без изменения общего DWH.

    | Домен	                       | Ответственность	                      | Технологии/Интеграция                                                         |
    | ---------------------------- | ---------------------------------------- | ----------------------------------------------------------------------------- |
    | Клинический (Медицина)	   | Данные пациентов, диагнозы, назначения   |	PostgreSQL / MongoDB (для JSON-историй)	API для ИИ-сервисов                   |
    | Финансовый (Финтех)	       | Счета, транзакции, кредиты 	          | PostgreSQL + Kafka (для потоковых платежей)	REST API для банковских сервисов  |
    | Аналитика и BI	           | Витрины данных, отчёты, KPI 	          | Snowflake + dbt (трансформации)	Подписка на события из других доменов         |
    | ИИ-сервисы	               | Обработка медицинских данных, прогнозы   |	Python + Feature Store (Hopsworks)	Чтение из Клинического домена через API   |
    | Операционный (HR/Логистика)  | Персонал, инвентаризация, оборудование   |	MySQL	Синхронизация с Финансовым доменом (бюджеты)                          |

3) Аргументируйте логику разделения на домены.

   Логика разделения

   | Домен	         | Критерии выделения	                                                                    | Примеры данных
   | --------------- | ---------------------------------------------------------------------------------------- | ---------------------------------------- |
   | Клинический	 | Данные, связанные с лечением пациентов (регулируются мед. стандартами, например, HL7).	| Диагнозы, истории болезней, назначения   |   
   | Финансовый      | Операции, требующие банковской лицензии и строгого аудита.	                            | Платежи, кредиты, счета                  |
   | Аналитика и BI	 | Агрегированные данные для отчётности (не требуют транзакционной целостности).	        | KPI, витрины, дашборды                   |
   | ИИ-сервисы	     | Данные для обучения моделей (высокие требования к качеству и актуальности).	            | Результаты МРТ, геномные данные          |
   | Операционный	 | Внутренние процессы, не влияющие напрямую на клиентов.	                                | Персонал, инвентаризация, логистика      |

   Ключевые преимущества для бизнеса в случае раделение на домены по схеме изложенной выше

   1) Гибкость и скорость вывода продуктов
      Пример: Запуск фармацевтического направления
      Было: Придётся расширять DWH, прописывать сложные ETL-процессы.
      Стало: Создаётся отдельный Фармацевтический домен с API для интеграции с BI.
    
    2) Снижение затрат на поддержку
       Автономность доменов уменьшает сложность системы:
       - Нет единой точки отказа (DWH).
       - Можно обновлять технологии точечно (например, только в финтехе).

    3) Соответствие регуляторным требованиям
       Данные изолированы по доменам:
       - Медицинские данные защищены по 152-ФЗ и GDPR.
       - Финансовые данные соответствуют банковским стандартам (PCI DSS).

    4) Ускорение аналитики
       Витрины данных строятся только на нужных доменах:
       - Финансовые отчёты — данные из Snowflake.
       - Медицинская аналитика — отдельный кластер (PostgreSQL).
    
    5) Безопасность
       Доступ к данным контролируется на уровне доменов:
       - Врачи не видят финансовые транзакции
       - Финтех-отдел не имеет доступа к мед. картам
