
1) Спроектируйте архитектуру системы через год

    Архитектурное решение для компании "Будущее 2.0"
    - Создание масштабируемой витрины данных (Data Marketplace) для самообслуживания аналитики.
    - Оптимизация IT-ландшафта с возможностью интеграции новых бизнесов без глубокой переработки DWH.
    - Отказ от легаси-систем (Power Builder, SQL Server 2008) в пользу современных решений (облачные хранилища, API-ориентированная архитектура).
    - Разделение данных по доменам (медицина, финтех, ИИ) с централизованным управлением доступом.

    Ссылка на диагрумму: https://drive.google.com/file/d/17k06Nj4kh0zm8laPqDUAyCS_SXo3p54B/view?usp=sharing

2) Опишите проблемные места

  | Категория	                  | Проблема	                                                                    | Последствия для бизнеса                                                                     |
  | ----------------------------- | ------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
  | Устаревшие технологии	      | SQL Server 2008, Power Builder, Apache Camel – морально устарели.	            | Высокие затраты на поддержку, невозможность масштабирования, риски безопасности.            |
  | Медленная аналитика	          | Сложные отчёты строятся часами из-за большого объёма данных и трансформаций.	| Задержки в принятии решений, недовольство пользователей, потеря конкурентного преимущества. |
  | Жёсткая связность DWH	      | Вся бизнес-логика зашита в DWH, новые сервисы требуют доработок хранилища.	    | Долгий вывод новых продуктов, высокие затраты на интеграцию.                                |
  | Нет единого доступа к данным  |	Данные разрознены (финансы, медицина, ИИ), нет единого каталога.	            | Сотрудники тратят время на поиск данных, дублирование отчётов, ошибки в аналитике.          |
  | Ручные процессы	              | Отсутствие автоматизации переноса данных (ETL/CDC).	                            | Ошибки в данных, задержки в обновлении отчётов, зависимость от ИТ-специалистов.             |
  | Сложность масштабирования	  | Добавление новых направлений (фармацевтика, электроника) требует переделки DWH.	| Замедление выхода на новые рынки, рост затрат на разработку.                                |
  | Узкое место – Power BI	      | BI-система завязана на DWH, сложные запросы нагружают сервер.	                | Падение производительности, ограниченные возможности для пользователей.                     |

  - Финансы: Устаревшие системы требуют дорогой поддержки, а медленная аналитика мешает оперативно управлять деньгами.
  - Конкуренция: Компании-конкуренты используют современные облачные решения и быстрее запускают новые сервисы.
  - Гибкость: Невозможно быстро добавить данные новых приобретённых компаний (фармацевтика, электроника).
  - Безопасность: SQL Server 2008 не получает обновлений – риск утечек и кибератак.

3) Приоритизируйте выявленные проблемы

    Матрица Эйзенхауэра

  |                                 Срочно                                                          |                            Не срочно                                      |
  | 1. Устаревший DWH (SQL Server 2008) – риски безопасности, несовместимость с новыми сервисами.	| 3. Ручные ETL-процессы – ошибки данных, но пока работают.                 |
  | 2. Медленная аналитика – блокирует принятие решений.	                                        | 4. Разрозненность данных – усложняет аналитику, но есть обходные пути.    |
  |                                                                                                 |                                                                           |
  |                          Срочно, но менее важно	                                                |                      Не срочно и не важно                                 |
  | 5. Power BI как узкое место – влияет на пользователей, но не ломает систему.                    |	6. Power Builder (легаси-интерфейс) – можно временно сохранить.         |

    MoSCoW-приоритизация

            Must Have (критично, без этого система нежизнеспособна)

        1) Миграция с SQL Server 2008 → на облачное хранилище (Snowflake/BigQuery).
           Почему: Риски безопасности, отсутствие поддержки, тормозит интеграцию новых бизнесов.
        2) Внедрение Data Marketplace с быстрыми отчётами.
           Почему: Бизнес теряет деньги из-за задержек аналитики.

           Should Have (важно, но можно временно обойтись)

        1) Автоматизация ETL/CDC (Kafka + Airflow).
           Почему: Снизит ошибки и нагрузку на DWH, но ручные процессы пока работают.
        2) Разделение данных по доменам (финансы, медицина, ИИ).
           Почему: Упростит масштабирование, но требует времени на реализацию.

           Could Have (желательно, но не обязательно)

        1) Замена Power BI на более гибкое BI-решение (например, Tableau + Looker).
           Почему: Улучшит UX, но это оптимизация, а не срочное исправление.

           Won’t Have (не сейчас)

        1) Рефакторинг Power Builder → переход на веб-интерфейс.
           Почему: Интерфейс устарел, но его замена не влияет на данные и бизнес-процессы.
